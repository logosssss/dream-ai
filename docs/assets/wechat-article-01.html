从 Dream-SaaS 到 Dream-AI：模块化单体 Agent 运行时开源

宋哥转AI · 公众号「Java宋转AI」 · Apache-2.0

Dream-SaaS 系列已按现网代码拆过 Graph、RAG、MCP、观测等多条线，重点是为什么这样切。

现仓模块多、进程多，跟一条完整请求成本偏高。需要一个更小、能 clone 就跑、边界仍与现网对齐的对照仓。

Dream-AI 即该对照仓：把 Agent 运行时主路径压进模块化单体——单进程、Port 分层、一次 invoke 覆盖网关、工具循环、会话 / Memory、RAG、观测，以及可选 MCP Client。

开源仓库

github.com/logosssss/dream-ai

01

和 Dream-SaaS 系列的关系

定位是系列的可运行附录，不是另一套产品叙事。

对照项 说明
Dream-SaaS 文章 多进程 / 多模块现网：平台化演进、审查、MCP 平台层、Graph
Dream-AI 仓库 同一套平台层思维，砍到一条主路径，便于跟代码与对照讲解
进程策略 现网 8090 / 8095 / 8096 分进程服务规模；沙盘先单进程跑通，Port 预留拆分切点
原则：先把「请求如何进入运行时」跑通，再谈服务拆分。切点已立在 Port 上，而不是事后硬拆类。
02

模块怎么摆

Maven 只保留四块，不为每个 Agent 再开空模块，也不复制现网 MCP 七层空架子。

dream-ai-kernel

Port 与运行时契约：Gateway、Chat、Tool、Memory、Conversation、Retrieve、Observe

dream-ai-knowledge

检索相关能力（进程内索引等），不绑厂商 SDK

dream-ai-agents

业务 Agent；当前仅 chat，只依赖 kernel 契约

dream-ai-app

装配层：HTTP、MyBatis / Redis / Vector、DashScope、MCP Client、Gateway 实现

03

主路径上有什么

业务入口只有一个 Agent：chat。能力点与系列文章反复强调的契约对齐。

网关　HTTP 只进 AgentGateway，统一装上下文再分发

工具循环　显式限步，避免「一调模型就失控」

会话 vs Memory　短历史落库；长期记忆走独立 Port

RAG　进程内检索结果写入 prompt，不由 Agent 直接碰存储

观测　traceId、耗时、modelCalls / toolCalls；另有 GET /api/observe

MCP Client　可选挂智谱 web_search；对照现网 Client→外部 Server，本仓不做自环 Server

REQUEST FLOW

POST /api/agent/invoke

　│

　▼ Gateway

　│　装 history / memory / retrieve

　▼ ChatAgent

　│　ChatPort + ToolCallingLoop

　▼ Response

　　　output + 观测摘要

04

几条硬边界（与现网同款）

下列约束来自现网踩坑沉淀，不是装饰性分层。

① Agent 不碰存储

不注入 Mapper / Conversation / Memory。业务只消费网关装好的上下文，避免 Agent 与持久化缠死。

② 厂商与 DAO 只在 app

kernel 只留 Port；DashScope、MyBatis、Redis、向量库装配全部落在 app。

③ 工具执行口统一

本地 ToolCallback 与 MCP 工具最终都进同一 ToolPort——贡献路径可以不同，执行与观测口径一致。与 MCP 系列中「平台层 vs 业务工具」同一套说法。

沙盘目标是能讲、能跑。名义上的「全家桶模块」若没有主路径流量，一律先不搬。
05

一次 invoke，Gateway 装什么

对照现网「平台组装上下文、业务不查库」：沙盘里 DefaultAgentGateway 在分发前完成三件事。

history = conversation.history(sessionId)

memoryNotes = memory.recall(sessionId)

hits = retrieve.retrieve(input, topK)

三者打进 Agent 入参后，再记一轮 Memory、写会话 turn、落观测。Agent 侧只看见字符串与 turn 列表，看不见 Mapper。

06

和已发文章怎么对照

系列主题 沙盘里盯哪里
MCP / 工具 ToolCallingLoop + 可选智谱 Client
观测 /api/observe 与响应中的 traceId / toolCalls（学契约，不抄 Admin UI）
RAG / 记忆 Gateway 如何塞 retrieve、memory，而不是 Agent 自行查库
平台层思维 kernel Port + app 适配器；模块少，边界不省

系列文章负责讲透现网为何复杂；Dream-AI 负责提供一条可改的主路径。两边对照，比只啃 60+ 模块现仓更省力。

07

本地怎么起

密钥与中间件走本地覆盖，不进仓库明文。

# 参考仓库根目录

cp .env.example .env

cp dream-ai-app/application-local.yml.example \

　 dream-ai-app/src/main/resources/application-local.yml

# 填 DashScope / 可选 ZHIPU_API_KEY 等

mvn -pl dream-ai-app -am spring-boot:run

冒烟：POST /api/agent/invoke，body 带 agentId=chat 与输入文本；响应中可读 output 与观测字段。
